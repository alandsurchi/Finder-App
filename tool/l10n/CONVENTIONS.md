# Finder localization conventions (for extraction workers)

Goal: every user-visible English string in your assigned files moves into the
localization system, and every layout in those files works right-to-left.
Do NOT restyle, rename widgets, or change behaviour. Smallest change.

## 1. How strings work
- Generated class: `AppLocalizations` (file lib/l10n/generated/app_localizations.dart).
- In widgets: `import 'package:finder/l10n/l10n.dart';` then `context.l10n.someKey`.
  Cache once per build when used a lot: `final l10n = context.l10n;`
- Outside widgets (services, providers, controllers, static helpers with no
  BuildContext): `L10n.current.someKey` (same import). Never store the result
  in a static/const; read it when the string is produced.
- Placeholders: `l10n.chatBlockTitle(userName)`; plural: `l10n.postsCount(n)`.

## 2. Where you put the English text
- Write ONLY to your own fragment file: `tool/l10n/fragments/<area>.arb`
  (JSON, `{"@@locale": "en", "key": "Text", "@key": {...}}`).
  Never edit lib/l10n/app_en.arb (generated by the merge) or other fragments.
- Reuse the seed keys in `tool/l10n/seed_en.arb` whenever the text matches
  exactly (commonCancel, commonSave, commonDelete, commonRetry, commonLost,
  commonFound, commonReturned, commonMarkAsReturned, commonFinderUser,
  commonSomethingWentWrong, commonUploadFailed(detail), relative time, etc.).
- New keys: camelCase, prefixed with your area prefix (given in your task),
  e.g. `postDeleteTitle`, `chatReplyHint`. Keys must be valid Dart identifiers.
- Identical text used twice inside your area → one key.
- Placeholders: `"chatBlockTitle": "Block {name}?", "@chatBlockTitle": {"placeholders": {"name": {"type": "String"}}}`.
  Numbers: `{"type": "int"}`. Plurals:
  `"postPhotosCount": "{count, plural, =0{No photos} =1{1 photo} other{{count} photos}}"`,
  `"@postPhotosCount": {"placeholders": {"count": {"type": "int"}}}`.
- Do not translate; English only. Keep the exact wording (fix nothing).
- Keep the "…" ellipsis character as it is in the source.

## 3. What counts as a user-visible string
Text(), labels, hints, tooltips, titles, subtitles, button labels, SnackBar /
ActionFeedback messages, dialog texts, Semantics labels, exception messages
thrown with ValidationException/UnknownException/etc. that reach the user,
enum display names, `describeError` fallbacks, chip labels, empty states.
NOT strings: route names, keys, URLs, API paths, JSON field names, asset
paths, log messages, `debugPrint`, test-only text, enum `.name` used for
the API, Hero tags, SharedPreferences keys, regexes, folder names
('avatars', 'chat'), analytics names.

## 4. Dates and times
- `relativeTime(ms, l10n: context.l10n)` and `shortDate(date, l10n: ...)`
  live in lib/core/utils/relative_time.dart and are already localized.
- Replace hand-rolled month/weekday arrays with `l10n.commonMonthShort('${m}')`
  and `l10n.commonWeekdayShort('${d}')` (both take the number as a String).
- Keep digits Western (0-9) everywhere; do not add intl NumberFormat.
- Date pickers (showDatePicker/showTimePicker) take the ambient locale
  automatically; if a `locale:` is passed, remove it.

## 5. Right-to-left checklist (apply in every file you touch)
Flutter mirrors Row, ListTile, Padding with *Directional* values, and most
Material widgets automatically. Fix only the hard-coded physical sides:
- `EdgeInsets.only(left: x)` → `EdgeInsetsDirectional.only(start: x)`; same for right→end.
- `EdgeInsets.fromLTRB(l, t, r, b)` where l != r → `EdgeInsetsDirectional.fromSTEB(l, t, r, b)`.
  Symmetric ones (l == r) can stay.
- `Alignment.centerLeft/Right, topLeft/Right, bottomLeft/Right` →
  `AlignmentDirectional.centerStart/End, topStart/End, bottomStart/End`.
- `Positioned(left: …)`/`right:` → `PositionedDirectional(start: …/end: …)`.
  `Positioned.fill` is fine.
- `BorderRadius.only(topLeft: …)` → `BorderRadiusDirectional.only(topStart: …)` etc.
  `BorderRadius.horizontal(left: …)` → `BorderRadiusDirectional.horizontal(start: …)`.
- `Transform.translate(Offset(dx, 0))` / drag deltas used for a side-specific
  gesture (swipe-to-reply, slide-to-cancel): multiply dx by `context.isRtl ? -1 : 1`
  so the gesture goes "inwards" in both directions.
- `TextAlign.left/right` → `TextAlign.start/end`.
- Chat bubble: "mine" aligns to end, "theirs" to start (use AlignmentDirectional).
- Icons: `arrow_back`, `arrow_forward`, `chevron_left/right`, `send`, `reply`,
  `help_outline`, `list`, `undo/redo`, `first/last_page` mirror by themselves.
  Icons that must NOT mirror (e.g. a play icon, a clock) need nothing.
  `Icons.keyboard_double_arrow_down` is vertical: fine.
- `Row(mainAxisAlignment: MainAxisAlignment.end/start)` is already directional.
- Phone numbers, e-mails, URLs, codes, prices, coordinates: wrap the Text in
  `Directionality(textDirection: TextDirection.ltr, child: …)` only if it is
  a standalone Text that mixes digits and symbols (e.g. "+964 750 …").
- `TextField` for e-mail/phone/password/URL: add `textDirection: TextDirection.ltr`
  is NOT wanted (Flutter handles it); only set `textAlign: TextAlign.start`.
- `Hero`, `Stack` without Positioned, `Column` need nothing.
- Custom painters/gradients using Alignment(x, y) for decoration (BeaconGlow,
  backdrop art): leave them; decoration does not need to mirror.

## 6. Verify
After finishing your files:
1. `python tool/merge_l10n.py` (merges all fragments, regenerates). If it
   reports a CONFLICT with another fragment, rename your key with your prefix.
   Another worker may run it at the same time; if gen-l10n output looks
   torn, just run it again.
2. `flutter analyze` must show no errors in your files (ignore the known
   pre-existing infos/warnings in exceptions.dart, main.dart, image_upload_service.dart).
3. `grep -nE "'[A-Z][a-z]+( [a-z]|…|\.|!|\?)" <your files>` to catch leftovers;
   justify any remaining literal in your report.
Report: files done, number of keys added, anything you could not localize
and why, RTL fixes made.
